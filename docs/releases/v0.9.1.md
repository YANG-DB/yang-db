# YANG-DB 0.9.1 — bug fixes

A bug-fix release on the 0.9 line. It fixes every issue that was open after 0.9.0: query results, the id generator,
the GraphQL schema, index mappings and several REST routes. Each fix comes with a test that failed before it. It still
runs on OpenSearch 2.19.7, and you don't need to reload or reindex your data.

| | |
|---|---|
| OpenSearch | **2.19.7** (Lucene 9.12) |
| Java | 11 |
| Branch | `release/0.9.x` |
| Previous release | [0.9.0](https://github.com/YANG-DB/yang-db/releases/tag/v0.9.0) |

## Upgrading from 0.9.0

Replace the engine (the Docker image or the distribution) and restart it. Indices, templates and data stay as they are. The mapping fixes (M1, M2) apply to unified indices and templates
created from now on; existing ones keep their mapping.
Check the [changes to note](#changes-to-note) below if you call the removed routes or use GraphQL on relationships
with several target types.

## Quick start

```bash
git checkout v0.9.1
cd docker
./buildDocker.sh Dragons        # builds the engine and the yangdb/yang.db:Dragons image
docker compose -f docker-compose-os.yml up -d
```

This starts OpenSearch 2.19.7, OpenSearch Dashboards and YANG-DB with the Dragons sample ontology. Then follow
`docs/tutorial/sample/dragons/README.md`, or open the playground at `http://localhost:8888/dragons/swagger`.

To run without Docker, unpack the attached distribution, then point it at your OpenSearch 2.19 cluster: in
`dragon/config/application.conf`, set `opensearch.hosts` (the shipped value, `"opensearch"`, is the Docker service
name) and `opensearch.http.port` (default 9200). Then run `dragon/start-fuse-service.sh`. The configuration is read
only from that file: the script's `--opensearch.*` flags have no effect.

## Fixes

**Query results**
- Two count conditions on the same relationship, such as `WHERE count(k) > 15 AND count(k) < 17`, now return the right
  rows. Before, the result was wrong (99 persons instead of 4 on the tutorial data). `OR` works too. (C3)
- A relationship property combined with a filter on the pattern's end entity no longer fails validation. (Q11)
- Range operators (`>`, `<`, in-range, in-set) on enumerated values no longer crash the planner's statistics. (P2)
- One query's elements no longer leak into the next query. This affected every query language. (Q13)

**GraphQL**
- A relationship with several target types now exposes all of them (as an interface or a union), instead of only the
  first. (G4)

**Index mappings (single-index provider)**
- A unified index now maps each relationship's `direction`, `entityA`/`entityB` and redundant fields, instead of
  leaving them to dynamic mapping. (M1)
- The unified index template now matches only its own index, not every index named after a type. (M2)

**Ids**
- The id generator now hands out consecutive ranges that never overlap, also with concurrent callers. Before, it
  returned the same range every time. (A6)
- The request-id worker id is taken modulo 64, as intended, not 4. (A7)

**REST routes**
- `POST /fuse/query/v1/run` runs the query instead of answering 404. (A9)
- `POST /fuse/query/cypher` and `/sparql` take the language from the URL; the body no longer needs a `type`. (A10)
- SPARQL is registered as `sparql`; `sparkQL` still works as an alias. (A5)
- A CSV load that fails as a whole now says why and answers 400, instead of 200 with empty lists. (A2)

**Tests**
- The index-provider test suite no longer wipes an OpenSearch that's already running on the test port (such as the
  Docker quickstart). It refuses to run unless you pass `-Dfuse.test.reuse_cluster=true`. (T3)

## Changes to note

- **Removed routes.** These routes never worked, so nothing that worked before stops working:
  - `/fuse/query/:id/elastic/view` and `…/page/:pageId/elastic/view` are gone, and so is the `elasticQueryUrl` field of
    the query resource. To see a query's OpenSearch requests, use the search slow log (see the
    [architecture tutorial](../tutorial/architecture/query-lifecycle.md#watch-it-yourself)). (A8)
  - In the Dragons extension: the `clause` routes, the `/ext` redirect, and the duplicate `cypher/logical/run` and
    `query/v1/logical/run` routes. The extension now contributes only the playground. (A4)
- **GraphQL on multi-target relationships.** `{ person { Own { name } } }` now returns both dragons and horses. A field
  that only one of the types has needs a fragment, such as `... on Dragon { power }`. (G4)
- **Failed loads answer 400.** A client that checked only the response body for `error` keeps working; one that
  treated every 200 as success now sees the failure. (A2)
- **`GET /fuse/idgen/init`** no longer resets an existing counter. (A6)

## Performance

Measured after the release, against v0.8.0 on OpenSearch 1.3 and v0.9.0, on the tutorial data and on 10 times it:
[docs/benchmark.md](../benchmark.md). In short: the same OpenSearch work as 0.8 on 1.3 (1,360 vs 1,360 shard
operations for the 29 queries both answer alike) and latency within run-to-run variation. The fixes in this release
change results, not cost: GQ4 now works, and R9 returns the right rows, in 61 instead of 239 ms at scale 10.

## Known limitations

- Tests fail when run against the packaged `fuse-core` jar (`mvn install` with tests). `mvn test` passes, and the
  distribution itself is not affected. (B1)
- Open issues are in `docs/revival/KNOWN_ISSUES.md`. Next: Phase 6 (OpenSearch 3.x on JDK 21, with Point in Time per
  cursor) and Phase 7 (speed and efficiency) in `docs/revival/ROADMAP.md`.
