# YANG-DB 0.8.0 — OpenSearch 1.3

The first release of the revived project, and the **last release on OpenSearch 1.3**.
The next release, 0.9.0, moves to OpenSearch 2.19.

| | |
|---|---|
| OpenSearch | **1.3.0** (also the version the engine's client libraries are built against) |
| Java | 11 |
| Branch | `release/0.8.x` (fixes for the 1.3 line go here; issues are labeled `opensearch-1.3`) |
| Download | `yangdb-0.8.0-distribution.tar.gz`, attached below (built from the tag by the Release workflow) |

## Quick start

The fastest way to try it is Docker: it runs OpenSearch 1.3.0, OpenSearch Dashboards and YANG-DB with the Dragons
sample ontology.

```bash
git checkout v0.8.0
cd docker
./buildDocker.sh Dragons        # builds the engine and the yangdb/yang.db:Dragons image
docker compose -f docker-compose-os.yml up -d
```

`docker/README.md` has the details.

Then follow the tutorial in `docs/tutorial/sample/dragons/README.md`. It covers loading the data and running the
example queries. The interactive playground at `http://localhost:8888/dragons/swagger` comes with the queries
already filled in.

To run without Docker, unpack the attached distribution, then point it at your OpenSearch 1.3.x cluster: in
`dragon/config/application.conf`, set `opensearch.hosts` (the shipped value, `"opensearch"`, is the Docker service
name) and check `opensearch.port` (transport port, 9300) and `opensearch.cluster_name`. Then run
`dragon/start-fuse-service.sh`. The configuration is read only from that file: the script's `--opensearch.*` flags
have no effect.

## What's in this release

This release collects the revival work from 2026: Phases 0–4 in `docs/revival/ROADMAP.md`.

**Builds and runs again**
- Pinned to OpenSearch 1.3.0, which still has the `TransportClient` the engine needs. The full build is green.
- One getting-started path, which is Docker. The README, docker docs and tutorial all agree on versions.
- The project README now lives in `PROJECT.md`.

**Smaller core**
- The Dragons sample domain moved out of the core build into `examples/dragons/`. The distribution is built by
  `distribution/` under the `dragons-assembly` profile.
- The old `dragons-sys-test` module is retired; the Docker end-to-end suite replaces it.

**Tests that test the right thing**
- Shared fixtures: one copy of the Dragons ontology and mapping, which removed drifted duplicates.
- Mapping and translator tests assert on the structure of the output rather than on hand-typed JSON strings. 21
  obsolete tests were deleted, and 11 previously ignored tests are enabled again.
- The Docker e2e suite (`docker/e2e/`) runs every query in the docs and the playground against a live stack.

**Query correctness fixes**
- Undirected patterns `-[]-` match both directions.
- Edge target types are respected.
- Same-id edges are no longer dropped.
- Count filters, the loader and several documented queries are fixed.

The complete list, with root causes, is in `docs/revival/KNOWN_ISSUES.md`.

**Extensions**
- A new `fuse-extension-api` module defines `YangDbExtension` and `QueryLanguages`. Extensions are discovered with
  `ServiceLoader`, so a new query language plugs in without editing core configuration files.
- GraphQL is now an extension (`extensions/graphql`), on graphql-java 24. Its queries are served at
  `/fuse/query/graphql`.

**CI**
- Every pull request runs the full build and test suite plus the Docker e2e suite. CodeQL runs after merges to main.

## Performance

The baseline for the later releases in [docs/benchmark.md](../benchmark.md): 1,360 shard operations and 1.4 s of p50
latency in total for the documented queries on the tutorial data; 3,444 operations and 9.0 s on 10 times it.

## Known limitations

- **OpenSearch 1.3 is end-of-life upstream.** Use 0.8.0 to run existing 1.3 clusters; new deployments should wait
  for 0.9.0 (OpenSearch 2.19).
- The engine talks to OpenSearch over the transport protocol (port 9300). REST-only clusters, such as managed
  services, are supported from 0.9.0.
- Open issues are tracked in `docs/revival/KNOWN_ISSUES.md`. Tests that are still ignored, with the reason for each,
  are listed in `docs/revival/IGNORED_TESTS.md`.

## Upgrading to 0.9.0

0.9.0 runs on OpenSearch 2.19.7. OpenSearch 2.19 opens indices written by 1.3, so an in-place upgrade of the cluster
keeps your data. The details are in `docs/revival/OPENSEARCH_MIGRATION.md` (on main).
